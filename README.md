# 📝 Todo List App

A full-stack Todo List application built to practice building and connecting a REST API with a React frontend. Create tasks, edit them, mark them complete, and delete them. Everything is saved in MongoDB.

---

## ✨ Features

- ➕ Create a todo with a description
- 📋 View todos retrieved from the backend
- ✏️ Edit a todo description
- ✅ Mark a todo as completed or incomplete
- 🗑️ Delete a todo
- 🛡️ Validate descriptions so empty or whitespace-only tasks can't be saved through the edit form
- 💬 Inline validation feedback while editing
- 💾 Persist todos in MongoDB
- 🧩 Separate frontend and backend responsibilities

## 🏗️ Architecture and Request Flow

### 🎨 Frontend flow

1. `App.jsx` loads the todo list when the component mounts.
2. `todoService.js` sends HTTP requests to the backend using Axios.
3. `TodoForm.jsx` collects a new task description and calls the add-todo service.
4. `TodoItem.jsx` displays a task and handles its edit, completion, and delete actions.
5. `App.jsx` owns the todos array and updates React state whenever a task changes.

### ⚙️ Backend flow

1. 🛣️ **Routes** map HTTP methods and URLs to controller functions.
2. 🛡️ **Validation middleware** checks request bodies using Zod schemas.
3. 🎮 **Controllers** handle request/response logic.
4. 📐 **Models** define the Todo document structure through Mongoose.
5. 🍃 **MongoDB** stores the persistent data.

### 🔄 Typical request path

```text
React component → Axios service → Express route → validation middleware → controller → Mongoose model → MongoDB
```

The response then travels back to the frontend, where the UI updates.

## 🗂️ Todo Data Model

| Field         | Type             | Description                                      |
| ------------- | ---------------- | ------------------------------------------------ |
| `_id`         | MongoDB ObjectId | Unique identifier generated by MongoDB/Mongoose  |
| `description` | String           | The task description (required)                  |
| `completed`   | Boolean          | Whether the task is complete (defaults to false) |
| `createdAt`   | Date             | Added automatically by Mongoose timestamps       |
| `updatedAt`   | Date             | Updated automatically by Mongoose timestamps     |

## 🔌 API Endpoints

The backend API is mounted at `/todos`.

| Method      | Endpoint     | Purpose                                                    |
| ----------- | ------------ | ---------------------------------------------------------- |
| ➕ `POST`   | `/todos`     | Create a todo                                              |
| 📋 `GET`    | `/todos`     | Retrieve all todos                                         |
| 🔎 `GET`    | `/todos/:id` | Retrieve one todo by ID                                    |
| 🔁 `PUT`    | `/todos/:id` | Replace/update a todo using the supported fields           |
| ✏️ `PATCH`  | `/todos/:id` | Partially update a todo (description or completion status) |
| 🗑️ `DELETE` | `/todos/:id` | Delete a todo by ID                                        |

### 📨 Example request bodies

**Create a todo — `POST /todos`**

```json
{
  "description": "Learn MongoDB",
  "completed": false
}
```

**Update completion — `PATCH /todos/:id`**

```json
{
  "completed": true
}
```

**Edit description — `PATCH /todos/:id`**

```json
{
  "description": "Practice React and Express"
}
```

> The create request requires both `description` and `completed`. The PATCH schema permits partial updates.

### 📬 Response notes

- `GET /todos` returns the list in a `Todos` property.
- `POST /todos` returns a success message and the newly created `todo`.
- Exact error response bodies depend on the controller and validation middleware.

## 🔐 Environment Variables

> ⚠️ Never commit real secrets or database credentials. Keep `.env` files out of Git using `.gitignore`.

### ⚙️ Backend — `backend/.env`

```env
PORT=3000
MONGODB_URI=your_mongodb_connection_string
```

Replace `your_mongodb_connection_string` with your own connection string. If you use MongoDB Atlas, make sure your database user and network access settings allow the connection.

### 🎨 Frontend — `frontend/.env` (optional)

```env
VITE_API_BASE_URL=http://localhost:3000/todos
```

The frontend falls back to `http://localhost:3000/todos` when this variable is not set. Vite exposes `VITE_`-prefixed variables to browser code, so never put secrets here. Restart the Vite dev server after changing them.

## 🚀 Installation and Local Development

Run the frontend and backend in separate terminals.

### 1️⃣ Clone the repository

```bash
git clone https://github.com/abhay-dot-dev/abhay_task33-Todo-List-App.git
cd abhay_task33
```

If Git created a folder with a different name, enter that folder instead.

### 2️⃣ Set up the backend

```bash
cd backend
npm install
```

Create `backend/.env` and set `MONGODB_URI`, then start the server:

```bash
npm run dev
```

The dev script uses Nodemon to restart on file changes, and the server connects to MongoDB before listening. It runs at 👉 `http://localhost:3000`

### 3️⃣ Set up the frontend

Open a second terminal at the project root:

```bash
cd frontend
npm install
npm run dev
```

Vite prints the local URL in the terminal, commonly 👉 `http://localhost:5173`

## 🖱️ Using the Application

1. ➕ Enter a task description and submit the form to add a todo.
2. ✅ Use the checkbox to mark a task complete or incomplete.
3. ✏️ Select the pencil icon to edit a description.
4. 💾 Select **Save** to persist the edit.
5. 🚫 Empty or whitespace-only descriptions are rejected by the edit form.
6. ↩️ Click outside the edit area or select the pencil icon again to exit editing. Unsaved changes are discarded.
7. 🗑️ Select the delete icon to remove a task.
